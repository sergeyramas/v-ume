# «В уме» 2.0 — план (ред. 2, после ревью Codex)

Дата: 2026-10-19. Основа: `docs/research/techniques.md`. Ревью: Codex gpt-6-sol (adversarial), вердикт ред. 1 «рано в реализацию» — замечания учтены ниже (§Что изменилось после ревью).

## Цель

Тренажёр для детей 9–15 лет, который:
1. **учит приёмам упрощения** сложения и вычитания: перед задачами объясняет приём, после ответа показывает, как ещё можно было решить;
2. **растит длину цепочки**, которую ребёнок складывает в уме, до 8–10 двузначных подряд на фиксированных условиях;
3. выглядит так, что хочется открыть ещё раз (новый визуал; «плита/накладная» уходит).

## Принципы (из исследования и ревью)

- **Зачёт только за самостоятельный ответ.** У каждой задачи статус: `сам` / `с приёмом` (подсказка 1) / `с шагом` (подсказка 2) / `с ответом` (подсказка 3 или «сдаюсь»). Звёзды и освоение считаются только по `сам` и `с приёмом`.
- **Ответ не виден до попытки.** Полное решение и «Реши по-другому» открываются только после ответа или «сдаюсь».
- **Меньше приёмов, но твёрдо.** 9 приёмов вместо 14; ребёнку достаточно 1–2 любимых способов на тип примера.
- **Помощь уходит по результатам, а не по счётчику.** 2 самостоятельных верных подряд — следующий разбор/«допиши» пропускается.
- **Честная обратная связь без наказания.** Ошибка — это разбор, а не падение плиты.
- Не обещаем «развитие памяти»: говорим «складываешь длинные цепочки».

## Приёмы (9)

| # | Ступень | Приём (детское название) | Признак (`fits`) | Объединяет |
|---|---|---|---|---|
| 1 | База | **Друзья числа и пары** | в списке есть пара *одного знака* с суммой 10/100/1000 (по единицам или целиком) | 1.1 + 1.6 |
| 2 | База | **Мост через круглое** | у первого слагаемого есть добор до ближайшего десятка/сотни, второе ≥ добора | 1.2 |
| 3 | База | **По частям: сотни → десятки → единицы** | второе слагаемое некруглое; для 3-значных — «слева направо» как 2-й уровень этого же приёма | 1.3 + 1.4 |
| 4 | База | **Почти круглое (+)** | слагаемое в 1–3 *ниже* или *выше* круглого (98 → 100−2, 102 → 100+2) | 1.5 |
| 5 | База | **Почти двойняшки** | |a−b| ≤ 2, оба двузначные | 1.7 |
| 6 | Средний | **Почти круглое (−)** | вычитаемое в 1–3 от круглого, без отрицательных промежуточных | 1.5 (−) |
| 7 | Средний | **Как сдача (добавляй вверх)** | a − b, разница ≤ 60 или a круглое | 1.8 |
| 8 | Средний | **Столбик разрядами** | 4+ двузначных одного знака, пар нет | 1.10 |
| 9 | Средний | **Плюсы отдельно, минусы отдельно** | смешанная цепочка, минусы в паре дают круглое | 1.13 |

«Убери нули» (1.12) — короткая заметка внутри задач с круглыми числами, не урок. «Опорное число», «равные добавки», «все из 9», проверка девятками — бэклог. **Прикидка** встроена: в разборе длинных цепочек последний шаг «сверь с прикидкой».

Каждая ступень заканчивается **смешанным уроком**: сначала «каким приёмом удобнее?» (выбор из 3, засчитываются все приёмы, у которых `fits`), потом счёт.

## Движок (`src/lib/engine/`)

```ts
type Line = { n: number; sign: 1 | -1 };  // инвариант: n целое 1..9999; первая строка sign=+1; ответ ≥ 0
type Op = { a: number; op: "+" | "−"; b: number; r: number; why?: string }; // одно устное действие
type Plan = {                 // решение приёма
  rewrite?: string;           // что «превращаем» (98 → 100 − 2), для анимации
  ops: Op[];                  // по порядку; r[i] — промежуточный результат
  answer: number;
};
type Blank = { prompt: string; expect: number };   // «допиши шаг»: одно число, не итог
type Technique = {
  id; title; level: 1|2; sign: string; mistake: string;
  why: { q: string; options: string[]; correct: number };
  fits(lines): boolean;
  generate(tier): Line[];               // гарантирует fits
  solve(lines): Plan | null;            // fits ⇒ solve ≠ null
  blanks(lines, plan): Blank[];         // задания на один шаг (компенсация, добор, остаток…)
  examples: [Line[], Line[]];
};
```

- **Валидатор `checkPlan`** (используется в тестах и в рантайме): каждый `Op` арифметически верен; цепочка `r` связна; итог = сумма строк; нет отрицательных промежуточных; все числа строк использованы ровно один раз со своим знаком.
- **`blanks`** спрашивают именно смысл приёма (сколько вернуть, сколько добрать, какая пара), а не итог; проверка по `expect`. Итог задачи — отдельный ввод.
- **`ways(lines)`** — приёмы с `fits && solve`; «Реши по-другому» показывается **только если есть ≥ 1 другой подходящий приём**, порядок — по ступени приёма, без «рейтинга выгоды».
- **Тесты (`engine.test.ts`)**: для каждого приёма 2000 случайных генераций → `fits`, `solve`, `checkPlan`; плюс таблица граничных примеров (0 в единицах, равные числа, 98/102, переход через 100/1000, повторы, минусы, порядок «меньшее − большее» отбрасывается генератором).

## Простые объяснения и ступень 0 (по образцу роликов Сергея, 19.10)

Цель: суть приёма понятна и тому, кто ещё не дошёл до этой темы в школе.
- **Ступень 0 — основы** (`story.ts`, `FOUNDATIONS`): «Что такое десяток» (кубики → палочка → сотня), «Друзья десятка», «Числовая прямая». У каждого приёма список нужных основ (`NEEDS`); не пройдена — показываем перед приёмом. Задания на основы — одно число (`foundationTask`).
- **Разбор — кадрами** (`story()` собирает их из настоящего решения): жизненная рамка «зачем» (сдача, монеты, чек) → что замечаем (красным только нужное) → превращение числа → шаги на числовой прямой или кубиках → итог с ✓.
- Правила кадра: одна мысль, ≤ 20 слов (проверяется тестом), на экране рождается только то, о чём речь; остальное бледное; красный — единственный акцент.
- Виды картинок: запись примера, числовая прямая с прыжками, кубики (десятки-палочки, единицы-кубики), итог.

## Урок приёма

Фазы (с адаптивным пропуском):
1. **Разбор** — анимация примера 1 (превращение чисел, скачки на числовой прямой для «моста»/«сдачи»), типичная ошибка, вопрос «почему так» (выбор). 
2. **Второй разбор** другого вида.
3. **Допиши** ×2 — `blanks` (пропускаются, если 2 предыдущих — `сам`).
4. **Сам** — 6 задач. Подсказки: «Подсказка» → 1 (приём и признак) → 2 (первый шаг); «Показать решение» = статус `с ответом`.
5. **Итог**: сколько `сам`, звёзды (3 = 6/6 сам, 2 = 5, 1 = 4), разборы ошибок, «Реши по-другому» на любой задаче.

**Близнецы:** задача со статусом `с ответом` или ошибкой → в очередь `twins` (тип = приём + tier). В уроке — через 3 задачи, если не успели — в следующую сессию (разминка дня).

**Освоение приёма** = 2 урока подряд с ≥ 5/6 `сам`. Не освоен — урок повторяется при следующем входе с разбором.

## Поток (длинные цепочки)

Числа показываются по одному и исчезают, ответ — итог. Только плюсы до ступени 7, далее с минусами. Лестница меняет **один параметр за раз**:

| Ступень | Чисел | Разряд | Показ | Минусы |
|---|---|---|---|---|
| 1 | 3 | 1-зн. | 3,0 с | нет |
| 2 | 3 | 2-зн. | 3,0 с | нет |
| 3 | 4 | 2-зн. | 3,0 с | нет |
| 4 | 5 | 2-зн. | 3,0 с | нет |
| 5 | 6 | 2-зн. | 3,0 с | нет |
| 6 | 6 | 2-зн. | 2,0 с | нет |
| 7 | 8 | 2-зн. | 2,0 с | нет |
| 8 | 8 | 2-зн. | 2,0 с | да (≤ 2) |
| 9 | 10 | 2-зн. | 2,0 с | да (≤ 2) |
| 10 | 10 | 2-зн. | 2,0 с | да (любое) |
| 11 | 10 | 2-зн. | 1,5 с | да (любое) |
| 12+ | 3-зн. — отдельная ветка «Сотни» (5 → 8 чисел), открывается после ступени 7 |

- **Правило:** 2 верных подряд — вверх (для режима «9–11 лет» — 3), ошибка — вниз на 1. Первые 3 задачи сессии без понижения; за сессию не выше чем +2 ступени; ниже 1 не падаем.
- **Генератор:** промежуточная сумма никогда < 0; доля переходов через десяток растёт со ступенью.
- **Контрольная точка:** в каждой 3-й задаче с 5+ чисел в середине показа спрашиваем «сколько сейчас?» (не влияет на ступень). Так видно, где сбился, и честный разбор: «на числе 4 у тебя было 143, должно 153 — потерял десяток». В обычных задачах формулировка «проверь по шагам, где мог сбиться» + все промежуточные суммы.
- **Рекорд** хранится по классу: «чисел × разряд × показ» (лучшая пройденная ступень), не «самая длинная» вообще.
- Пауза при уходе вкладки в фон (показ замирает, задача переигрывается). Озвучка — опция. Настройка «помедленнее» (+0,5 с) для младших.

## Повторение (Лейтнер)

Карточка = **тип**: `techniqueId:tier` или `flow:ступень`. Коробки 1–4 с интервалами: в этой сессии → 1 день → 3 дня → 7 дней.
- ошибка или `с ответом` → коробка 1; `с шагом` → остаётся; `сам`/`с приёмом` → +1 коробка; после коробки 4 — карточка снята.
- Пропуск дней ничего не ломает: всё просроченное выдаётся по старшинству, максимум 6 карточек за разминку.

## Разминка дня (~5 минут)

Просроченные карточки (≤ 6) + 1 подход Потока (5 задач с текущей ступени). Счётчик «дней подряд» (без наказания за пропуск — просто сброс).

## Экраны

1. **Путь** — две ступени приёмов + смешанные уроки, «Разминка дня», плитка «Поток» (ступень, рекорд), дни подряд, переключатель возраста при первом входе.
2. **Справочник приёма** — то же, что фаза «Разбор», открывается в любой момент.
3. **Урок** (фазы выше).
4. **Поток**.
5. **Разминка**.
6. **Прогресс** — простой: освоенные приёмы, ступень Потока и рекорды, дни подряд. Графики — в бэклог.

## Визуал

Скилл `impeccable` (new-work, новый визуальный мир). Требования: светлая тема; крупные цифры; **анимация превращений чисел** как главный приём подачи (98 → 100 − 2, пара «склеивается» в 100); единый цветовой код разрядов (сотни/десятки/единицы) во всём приложении; числовая прямая для скачков; `prefers-reduced-motion`; шрифты с кириллицей; без сюжета-метафоры, тон — уважительный и к 9-летнему, и к 15-летнему (без «малышовости»). Сначала макет 3 экранов (разбор приёма, задача с подсказкой, Поток) → согласование с Сергеем → сборка.

## Технические рамки

- Стек остаётся: TanStack Start + Vite + zustand. Каркас Grok (auth, PGlite, p2p, PWA) не трогаем; в `__root.tsx` меняем только мету/описание.
- Деплой: на Vercel нет `DATABASE_URL` → `db:migrate` пропускается (проверено 19.10). Превью-деплой → смоук: прямое открытие `/lesson/<id>`, перезагрузка с прогрессом, гидратация.

## Критерии готовности

1. 9 приёмов по таблице; тесты движка (2000 генераций × приём + граничные) зелёные; `checkPlan` проходит для всех `solve`.
2. Урок: статусы зачёта, подсказки 1–2, решение только после ответа/«сдаюсь», «допиши» спрашивают смысл приёма, адаптивный пропуск, близнецы.
3. «Реши по-другому» после ответа, только при реальной альтернативе.
4. Поток: таблица ступеней, правило вверх/вниз с защитами, контрольные точки, рекорды по классу, пауза в фоне.
5. Лейтнер и разминка дня по правилам выше.
6. Новый визуал; проверен на 375 / 768 / 1440, с длинным объяснением, ошибкой, подсказками, озвучкой выкл/вкл, reduced-motion.
7. `typecheck`, `test`, `build` зелёные; превью на Vercel + смоук; прод — после «да» Сергея.
8. **Пилот (Сергей):** 1–2 ребёнка, 3 дня. Смотрим долю `сам`, долю «показать решение», ошибки знака/переноса, ступень Потока на день 1 и 3. По итогам калибруем лестницу.

## Порядок работ

1. Движок + тесты.
2. Макет визуала (3 экрана) → согласование.
3. Путь, справочник, урок, подсказки, «Реши по-другому».
4. Поток.
5. Лейтнер, разминка, прогресс.
6. QA (браузер, 3 ширины), превью-деплой, показ.

## Что изменилось после ревью Codex

- Блокер «ответ виден до попытки» → статусы зачёта, решение и «способы» только после ответа.
- Блокер «fade/проверка шага» → вместо скрытия шагов — `blanks`, спрашивающие смысл приёма; валидатор `checkPlan`.
- Блокер «тест доказывает мало» → `checkPlan` (связность, знаки, без отрицательных, все строки ровно раз) + граничные примеры; минусы не переносятся в конец молча — это отдельный приём 9.
- Блокер «где сломалось» → контрольные точки в Потоке + честная формулировка в остальных.
- 14 приёмов → 9 (объединены дубли, «опорное число» в бэклог).
- Лестница Потока переписана «один параметр за раз», защиты от падений, рекорд по классу.
- Лейтнер и близнецы описаны как алгоритм; убраны графики и «слабые типы».
- Добавлены: возрастной режим, reduced-motion, пауза в фоне, проверка 768, пилот.
- Риск `db:migrate` проверен: на Vercel нет `DATABASE_URL`, миграции пропускаются.
